# E-Commerce Insights: Web Scraping and ETL Pipeline

An automated data-extraction pipeline that collects **product, pricing and review data** from e-commerce sites with
**BeautifulSoup** (static pages) and **Selenium** (JavaScript-rendered pages), then runs it through an **ETL
workflow**: cleaning, normalisation, duplicate removal and validation, before loading it into SQLite and analysing
it for pricing trends.

> This is a clean, documented rebuild of my third-year project (web scraping for e-commerce insights). The code in
> this repository was written in 2026 and the Git history reflects that.

## Pipeline

```
  BeautifulSoup scraper  ─┐
  (static HTML sites)     ├─>  raw records  ─>  clean  ─>  de-duplicate  ─>  validate  ─>  SQLite + CSV  ─>  report
  Selenium scraper       ─┘    (all text)      typed      exact + near       rules +        products,        pricing
  (JavaScript sites)                           records                       reject log     history,         insights
                                                                                            reviews
```

| Stage | What it does | Code |
| --- | --- | --- |
| Extract (static) | Walks listing pages and product pages with BeautifulSoup, follows pagination, tolerates broken pages | `scrapers/books.py` |
| Extract (dynamic) | Drives Chrome with Selenium: presses "Load more" until the list is complete, expands lazily loaded reviews, then parses the final DOM | `scrapers/dynamic.py` |
| Polite fetching | Identifying User-Agent, **robots.txt enforced**, rate limit, retries with backoff, optional on-disk page cache | `http.py` |
| Clean | Prices in many formats (`£51.77`, `$1,299.00`, `1.299,00 €`, `Rs. 1,200`), currency detection, text-rating to number, stock parsing, whitespace/Unicode normalisation, repair of mis-decoded characters (`Â£` -> `£`) | `etl/clean.py` |
| De-duplicate | Exact (same source and id, keeps the most complete and newest copy) and near duplicates (same title and price under a different id) | `etl/dedupe.py` |
| Validate | Rules for title, price range, rating range, URL, ids. **Rejected rows are stored with the reasons**, never silently dropped | `etl/validate.py` |
| Load | SQLite tables `products`, `price_history` (one row per run), `reviews`, `rejects`, `runs`, plus `products_clean.csv`, `rejected.csv` and a JSON quality report | `etl/pipeline.py` |
| Analyse | Price statistics per category (currencies never mixed), price/rating correlation, best-value products, price changes between runs, cross-source price comparison, charts | `analysis/insights.py` |

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e .

python -m ecom_insights demo          # offline: runs the ETL on a bundled messy catalogue and writes a report
```

The demo needs no network and no browser. Output goes to `data/output/` (`report.md`, charts, CSVs, quality report).

### Scrape the practice bookstore (static pages, BeautifulSoup)

```bash
python -m ecom_insights scrape books --pages 3 --cache-dir data/cache     # 3 pages = 60 books, with product pages
python -m ecom_insights report
```

[books.toscrape.com](https://books.toscrape.com) is a sandbox site made for scraping practice (1,000 books).
Leave out `--pages` for the whole catalogue (about 1,050 requests at the default 1 s delay).

### Scrape a JavaScript-rendered shop (Selenium)

Needs Google Chrome installed (Selenium Manager fetches the matching driver automatically).

```bash
python -m ecom_insights demo-site                      # terminal 1: bundled JS shop on http://127.0.0.1:8000
python -m ecom_insights scrape dynamic --url http://127.0.0.1:8000        # terminal 2 (add --headed to watch)
python -m ecom_insights report
```

The demo shop ships its products through a JSON API and renders them with JavaScript, loads 12 at a time behind a
"Load more" button, and loads reviews lazily per product. To target another site, pass your own `Selectors` to
`dynamic.scrape()`.

Running a scrape several times builds a **price history**: the report then lists which prices changed between runs.

## What the demo ETL does

The bundled catalogue deliberately contains the problems real scrapes have. `python -m ecom_insights demo` prints:

| Stage | Records |
| --- | --- |
| Extracted | 75 |
| Exact duplicates removed | 2 |
| Near duplicates removed | 1 (same listing re-posted under a new id, different casing) |
| Rejected | 3 (2 missing prices, 1 negative price) |
| **Loaded** | **69** |

Also handled: a price in a different currency (kept as EUR and never averaged with USD), an out-of-range rating
(set to missing), stray whitespace and casing in titles.

## Responsible scraping

- Scrape only sites that allow it. The built-in targets are practice sites made for this purpose.
- `robots.txt` is checked before every request and disallowed URLs are skipped.
- Requests are rate-limited (default 1 s), retried with backoff, and can be cached to avoid re-downloading pages.
- The User-Agent identifies the bot. Check a site's terms of service before pointing the scraper at it.

## Limitations

- The scrapers target specific page structures. A different site needs new selectors (BeautifulSoup parsing in
  `books.py`, a `Selectors` object for Selenium).
- The Selenium scraper has been exercised against a fake browser and the demo shop's JavaScript, but not with a
  real Chrome session in the automated tests. Run the Selenium quick start above once on your machine to confirm.
- The pipeline is designed to handle large runs (SQLite, streaming scrape generators), but this repository ships
  no pre-scraped dataset, so no claim is made about a particular record count.
- Prices in different currencies are reported separately; no exchange-rate conversion is done.
- Near-duplicate detection is exact-match on normalised title and price, not fuzzy; cross-source comparison uses
  fuzzy title matching.
